# ELS 基坑支护模板工作台

模板工作台 v0.2，面向Windows。根据已确认计划，以既有Excel计算书及DWG图纸模板为设计依据。

## 已可使用

- 项目、场地、外部验算记录及构件工况内力录入。
- 单位／内力性质检查，位置、标高、重复工况及跨工况几何一致性检查。
- SQLite项目历史版本保存与重开、数据库备份、完整输入项目JSON导入导出。
- 构件平面位置示意，仅读取Excel模板结构及公式样例。
- 模板文件指纹和审核资料检查。
- 连续钢板桩墙分为两个独立流程：截面初选比较模板六种型号，指定截面验算只验证分析模型已经采用的型号。
- 独立输入各工况未乘1.4的模型剪力、弯矩；使用绝对值包络并记录各自控制工况，由Excel放大1.4一次。
- 选型号后按工程师附表自动读取尺寸、每根／每米墙截面属性与重量，E采用205 kN/mm²，屈服强度采用工程师确认的275 MPa。
- 只需输入设计折减系数（剪力、弯矩共用）和EI折减系数Bd，自动计算EI及折减EI。
- 分析模型直接采用Excel生成EI，取消重复核对环节；自动选型改变型号或刚度时仍提示重新分析。
- 同步两张工作表的Wall Property型号，生成待复核的XLS副本、单页PDF及结果JSON；刚度与模型不符时标记须重新分析。

## 当前限制

钢板桩模块已接入本机选定模板的FSPiv Summary第50行，完成六型号及超限软件验证；支撑、围檩、两类直接角焊缝及Blinding已接入计算书模板。尚未完成三个代表工程验证或全部香港规范审核，完整节点设计、整体稳定和DWG出图仍待实施。
输入格式检查或钢板桩两项验算通过不代表整体设计通过。输出始终标记待工程师复核，带lagging的其他组合不纳入本模块。
原模板其他工作表保留为非常隐藏状态以保留公式来源，其中历史错误不代表已处理；它们不参与本模块评估和PDF输出。

本地钢板桩映射位于templates/sheetpile-structure.local.json，不上传版本库。模板修改后指纹失配会停止生成，需要重新审查登记。
项目输入和历史版本包含钢板桩参数。改动输入后，界面会标记先前成果过期；每次生成保留独立版本。模型采用EI由所选型号及Bd生成；旧项目已经记录的模型EI保留，直到修改型号或Bd。

## 启动

本项目电脑已建立 `.venv`；双击根目录的 `启动软件.cmd`。

启动时先弹出Project Setup，填写英文Project Name及Subject Name后进入工作台。这两项随项目版本保存，可在“项目与场地”修改，并直接写入生成计算书的Project／Subject栏。
生成Excel使用英文文件名和表格内容，去除末尾五行说明，内容下方预留两行空白再画粗外框，采用水平及垂直打印居中、0.25英寸窄页边距及自动适配单页。参数来源、控制工况等追溯资料仍保存在result.json。

其他Windows电脑先安装Python 3.12或更新版本，在项目目录执行：

```powershell
./setup.ps1
./启动软件.cmd
```

钢板桩生成需要Microsoft Excel桌面版，基础录入不依赖Excel。CAD目前检测到浩辰CAD，接口和DWG对象映射待验证。
当前依赖范围见requirements.txt，实际验证版本见requirements-lock.txt。

## 模板资料

将Excel与对应DWG复制到templates目录，另提供一个完整已复核项目及分析来源。
工程模板、项目数据库、生成成果及虚拟环境默认不提交GitHub。
版本库中只保存代码、非工程测试数据和文档。

## 钢板桩模块使用

1. 打开“钢板桩结构计算 → 截面初选”，输入两个折减系数和参考内力，比较六种型号及刚度；初选仅保存比较记录，不生成验算XLS/PDF。
2. 点击“采用拟选型号”，型号和系数转入指定截面验算页，原验算内力清空。使用拟选型号及Excel刚度完成外部分析。
3. 在“指定截面验算”填写模型采用的型号、两个折减系数及该型号分析后的内力与来源；已有确定型号可直接使用此页。
4. 点击“验算指定型号并生成计算书／PDF”。软件不更换型号，成果位于outputs/sheetpile的独立版本目录。
5. 两页独立保存输入；旧版本自动选型输入转入初选页，不自动用于指定截面验算。初选记录位于outputs/sheetpile-preselection。

软件验证样例位于outputs/sheetpile-validation，明确标注非新项目设计。Excel重算验证脚本为python -m tools.verify_sheetpile_excel，仅在本机真实模板已登记时运行。

## 围檩与支撑计算书（v0.5）

进入“围檩／支撑计算书”，页面顶部有“生成围檩／支撑计算书及 PDF”按钮。独立生成不要求先填写钢板桩参数。勾选“在钢板桩计算书中同时加入”后，也可由钢板桩页生成同一本联动计算书。

- Struts区域：输入未乘1.4的墙法线方向力F（kN）、支撑间距s、角度以及Strut length。角度为支撑轴线与墙法线夹角，设计轴力为1.4F/cos(angle)，不再另乘间距。自重剪力及弯矩使用Strut length，Lx默认跟随它；手动修改Lx后保留修改值。勾选Lx=Ly后，Ly自动跟随Lx。
- Waling区域：选择关联支撑及工况，荷载宽度自动取该支撑间距，分布荷载q=F/s；Span手动输入，整段按均布荷载处理。沿用模板N=1.4qs、V=1.4qSpan/2、M=1.4qSpan²/8。围檩不设置角度。
- 截面下拉框支持输入尺寸片段搜索，例如203；截面属性由原模板库读取。“按选中行批量新增”复制参数并自动生成唯一编号，已录入的关联焊缝也随构件复制。
- 焊缝区域有记录时自动加入连接验算，没有记录时仅生成构件验算。连接范围仍为直接无偏心支撑／角撑—围檩、围檩—钢板桩角焊缝。
- Blinding为可选项。勾选后使用钢板桩页剪力包络、项目短边及用户输入厚度，仍采用工程师指定的Blinding模板。未勾选时不要求钢板桩数据、基坑长宽或垫层厚度。

新版独立生成直接使用工程师指定的Structural capacity AA section.xlsx及其中的构件、截面库、Connection check和Bracket工作表，输出XLSX与PDF，不再先打开旧XLS。成果位于outputs/supports的版本目录，文件名Waling_Strut_Check_Review.xlsx/.pdf。输入修改后原成果标记过期；从软件重新生成新版本，以保持结果记录与文件一致。源模板与既有成果保留。

Weld／Bracket／Blinding区域新增托架输入：关联围檩及工况、托架截面及材料、托架长度、托架间距、围檩重心到墙距离、焊脚、焊缝强度及总有效焊长。围檩重量为其每米自重乘托架间距；设计剪力为1.4倍围檩重量加1.4倍托架自重，设计弯矩为围檩设计重量乘重心距墙力臂，再加托架自重的悬臂均布荷载弯矩。0.5m仅为原案例的重心力臂，不再当作荷载宽度。

围檩—钢板桩、托架及其连接、支撑／角撑—围檩的连接验算集中在Connection Checks同一页，保留模板三段结构。完整托架构件剪力、弯矩、截面及屈曲验算采用AA模板的Bracket页，作为独立明细页输出。托架焊缝沿用模板的直接剪力比较，未增加焊缝群弯矩传递验算；这一范围在托架明细页明确注明。旧模板的固定OK与失效项目引用不沿用。

AA模板登记与指纹保存在本机templates/supports-structure.local.json；需要接入修改后的模板时，先审查，再运行python -m tools.register_supports_template。原文件只读取快照，验证期间请先保存关闭，避免自动保存改变指纹。软件验证脚本为tools.verify_aa_connections_excel与tools.verify_aa_connection_links。

旧项目的支撑kN/m值按原间距转换为墙法线力kN，保留原计算轴力和自重长度；能唯一识别的围檩关联自动恢复，无法唯一识别时需手动选择关联支撑。Excel验证脚本包括tools.verify_supports_v2_excel及tools.verify_support_button，要求本机已登记模板和已有基准样例。

## 本地 Git 工作副本

本项目使用GitHub仓库`tianrenshi7136-hue/11`，开发分支为`feat/template-workbench`。当前项目文件夹可直接作为本地Git工作副本；工程模板、数据库、生成成果、凭据和临时诊断脚本由`.gitignore`排除，代码换行规则由`.gitattributes`统一。

在项目目录运行`git status`查看变更，运行`git log -5 --oneline`查看版本。提交前检查`git diff --cached --name-only`，确认不包含工程资料。GitHub连接的授权与命令行Git登录分别管理；命令行推送需要该电脑可用的GitHub凭据。
