# v0.7.2 计算书及PDF生成性能优化

## 范围与原因

工程师已同意实施第一阶段性能方案。保留真实Excel计算引擎、现有工程方法、缺失输入保护、公式错误检查、外部链接核对、NOT PASS输出及打印效果。本次没有建立工程计算结果缓存、预处理模板缓存，也没有删除历史模板页。

优化前，对同一份7页完整软件验证输入的分析计时为143.195秒。程序将打印内容以下的空白行一直隐藏到第65,536行，使Excel的UsedRange膨胀；随后读取28张表的UsedRange.Formula，在Python中检查约31,571,892个单元格。COM调用也频繁逐单元格设置格式及向打印系统提交页面设置。PDF导出本身约需3秒，并非主要耗时。

## 实现

- 用Excel原生Find查找CELL(filename)元数据，在所有保留的表内清理路径；不再把整张UsedRange传回Python。
- 根据实际含值或含公式的最后一行隐藏历史内容，由明确的PrintArea排除空白尾行。公式错误检查仍覆盖适用打印区域。
- 利用PrintCommunication集中提交打印参数，导出前明确提交；仅为实际打印页配置页眉页脚，不对非常隐藏的历史页重复触发打印器设置。
- 对汇总表数字格式、字体、边框和相同行高合并操作；边框识别只读取小范围数据，并保留原合并单元格的表格边线。
- 同次生成共享一个只读参考工作簿，关闭时释放；每次点击生成仍使用独立Excel会话及独立成果副本。参考原文件不被编辑。
- 移除指定钢板桩截面的重复计算。使用Excel接口类型信息减少反复解析调用；这只涉及软件接口，不缓存工程计算输入或结果。
- 界面增加阶段文字和活动进度条，完成显示总耗时。result.json的performance记录validate、open_excel、prepare_template、sheetpile、members、member_summary、connections、blinding、finish_layout、verify_formulas、verify_links、save_excel、export_pdf及close_excel的实际秒数；不存在的阶段不记录。

## 本机测量

| 流程 | 实测耗时 | 说明 |
|---|---:|---|
| 优化前7页 | 143.195秒 | 带函数分析器的基准，同一份软件验证输入 |
| 第一轮优化7页 | 70.249秒 | 完整结果与公式比对通过 |
| 集中打印与格式优化7页 | 57.557秒 | 带分析器验证 |
| 最终7页 | 43.839秒 | 正常生成，包含钢板桩、汇总、支撑、围檩、连接、托架、垫层 |
| 最终6页 | 40.202秒 | 独立围檩／支撑入口，其他模块同上 |

最终7页相对于已测基准约缩短69.4%，本机标准验证案例达到一分钟目标。最终正常生成的阶段记录：Excel启动打开约6.34秒，构件生成5.64秒，汇总2.78秒，连接及托架10.85秒，垫层2.54秒，布局3.74秒，保存1.60秒，PDF3.09秒，其他时间为模板准备、各项检查及关闭。完整总时间包含这些步骤。

数据只代表该电脑和该输入，不作为任意构件数量下的固定完成时间承诺。首次生成接口代码、Excel或打印器状态、OneDrive文件读取、构件和工况数量均会影响耗时。跨越电脑暂停期间的计时未纳入上述结论。

## 验证

- 68项自动测试通过，包括打印状态异常恢复、提交前后状态、实际尾行范围、隐藏表路径清理、只读参考复用及异常关闭、进度提示不改变工程输入。
- 真实Excel生成7页及6页成果。全部计算结果、选定截面、控制工况、验算状态以及打印范围内公式、缓存值与基准逐项比较；只排除TODAY产生的当前报告日期。
- 围檩剪力继续为4000kN；改变支撑轴力不影响该焊缝，改变围檩剪力使焊缝同步更新，多个围檩的最大剪力选择随输入切换，清空必需剪力仍显示CHECK INPUTS。验证在临时副本内完成。
- 生成过程中检查打印区公式错误，清理外部链接并比较清理前后数值，验算失败保留NOT PASS。
- 7页PDF文字、页数、尺寸、边框矢量位置一致。6页PDF与基准对应页面的文字、尺寸、外框范围和渲染一致；Excel将部分相接边线拆分为不同矢量段，但画面未改变。报告日期单独排除。108dpi渲染比较的最大变化约0.023%像素，仅在少量文字抗锯齿位置；其他页面像素一致。
- 人工查看钢板桩页及连接页，确认外框、空白行、表格封线及4000.00kN显示。

本地验证成果位于outputs/performance-validation和outputs/performance-validation-supports；这些目录、工程输入及模板不提交GitHub。汇总记录为outputs/performance-validation-result.json及outputs/performance-validation-supports-result.json。

## 复现

在已登记本机参考模板、已安装Microsoft Excel及保存基准样例的项目环境执行：

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -q
.venv/Scripts/python.exe -m tools.verify_performance_excel
.venv/Scripts/python.exe -m tools.verify_performance_excel --supports-only
```

加--profile可记录函数计时；--result指定现有result.json只进行比较，不再生成。PDF外观验证脚本为tools.verify_report_pdf，需Poppler、pdfplumber、Pillow和NumPy；跨日期比较加--allow-report-date。原生Excel联动回归使用tools.verify_waling_weld_excel --result指定新成果记录，在临时副本中验证。

关闭并重新启动工作台后使用v0.7.2。历史成果不会覆盖，新生成文件仍按独立时间版本保存。
